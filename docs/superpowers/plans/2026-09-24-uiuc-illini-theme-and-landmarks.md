## 1. 这个仓库是什么（改造前的约束事实）

- Three.js r170，纯原生 ES module，**没有构建步骤、没有 package.json、没有测试框架**。`index.html` 用 importmap 从 jsDelivr 拉 three，所以验证时必须联网。
- `ARCHITECTURE.md` 是硬契约：1 unit = 1 m、Y 轴向上、朝向 = `rotation.y`、前向 = `(sin h, 0, cos h)`、模型朝 +Z；**唯一依赖是 three**；帧循环内不许抛异常；`dispose()` 必须回收（重开局会重建整个世界）。
- 模块归属（改文件时遵守，别顺手越界）：
  | 文件 | 归属 | 本轮是否动 |
  |---|---|---|
  | `track.js` / `environment.js` / `track-textures.js` | Agent 1 · World | **动** |
  | `models.js` | Agent 4 · Art | **动**（仅道具模型） |
  | `styles.css` / `hud.js` / `config.js` / `main.js` | Agent 5 · Game & UI | **动** |
  | `kart.js` / `ai.js` / `input.js` / `race.js` / `camera.js` / `audio.js` / `events.js` | Agent 2 / 5 | **不动** |
  | `effects.js` | Agent 3 · FX | **只读**（原因见 §8.6） |
- 验证手段只有两件：`dev/track-test.html`（几何自检，打印 build ms / 中线偏差 / racing line 出界数）和 `dev/drive-test.html`（开车）。加上 `window.__game`（`main.js:562`）暴露的调试口。

### 3.2 为什么天空不做成"橙蓝对撞"
橙色全部给**地面元素**（路缘、护栏、看台、建筑、加速板、UI），天空保持可信的伊利诺伊晴空（工业蓝 → 浅蓝）。把地平线染橙看着像日落，会同时压掉赛道对比度、弄脏远处地标剪影——而这一轮的全部价值就在"远处能认出哪些楼"。橙蓝的成立靠**同一画面里的橙物件 + 蓝物件**，不靠一个橙天空。

## 7. 分阶段任务

### P0 · 基线（约 0.5 h，必做）
1. `git checkout -b illini-theme`（当前是 `c52aca3` 干净工作区）。
2. 起服务：`py -3 -m http.server 8080`（**本机 `python` 是 2.7，不能用**）。
3. 采集基线并记录下来：
   - `dev/track-test.html` 日志：`build ms`、`centerline mismatches`（应 0）、`racing line offroad`（应 0）、8 个发车位的 `onRoad`。
   - `window.__game.renderer.info.render`（triangles / calls）、`info.memory`（geometries / textures）。
   - 六屏截图：title / select / race / items / results / pause。
   - 帧率基线：rAF 里取 120 帧均值（放 `tmp/` 里的临时页或控制台跑）。
4. 在 `tmp/` 放一份"验收清单"文本，后面每个阶段照抄着过。

### P1 · 换色（约 0.5 天，只改颜色，不动几何）
按 §3.1 全表替换。收口标准：
- `dev/track-test.html` 的 `centerline mismatches` / `racing line offroad` **与基线完全一致**。
- 六屏截图能看出"橙蓝"，且赛道可读性没有下降（路缘、跳台、加速板在 300 km/h 下仍分得清）。
- `window.__game.errors()` 为空数组。

### P2 · 地标（约 1–1.5 天，新建 `src/landmarks.js`）
顺序**先远后近**（先立骨架、再填细节；每一步都能截图）：
1. #10 平原/筒仓/风机/水塔（先把"热带"换成"伊州"，收效最大）
2. #1 + #2 体育场群（起跑直道，改现有看台而非新增 —— 起跑直道两侧被 `standZones` 占着，`spot()` 会拒绝新落点，见 `environment.js:404–422`）
3. #3 + #4（Union + Alma Mater）
4. #5 Altgeld、#6 McFarland（替换 lighthouse）
5. #7 Foellinger（远观锚点，单独一次提交单独截图）
6. #8 Siebel、#9 Morrow Plots
7. #11 乐队看台、#12 入口标牌

每个地标一次提交，每次提交都重跑 P1 的收口标准。

### P3 · 道具与道具化（约 0.5 天）

## 12. 第二轮：赛道起伏（用户反馈「赛道太平面，要陡」）

第一轮冻结了赛道几何；这一轮解冻**海拔**，x/z 一个数不动——拐弯形状、地标锚点、桥、道具行全部继续有效，改的只是 `track.js` 的 CP 表 y 列。

### 12.1 剖面设计

| 区段 | 变化 |
|---|---|
| 起跑直道 | 1.5 → 5，几乎平（发车公平） |
| 大左扫弯 | **爬坡**：5 → 14 → 24（最陡爬坡 15.8%，t≈0.25）| 
| 坡顶 | **+34 山顶**（t≈0.30），全校园展开在眼前，跨顶后下坡 |
| S 弯 | **下坡**：30 → 18 → 10 → 6（-15%）|
| 桥前爬坡 | 6 → 8 → **20**（13% 陡爬，桥上 21 m 悬空）|
| 桥后 | **陡降 18 m/88 m：-24%（t≈0.61）**，共 3 个跳台 |
| 后段 | 坡顶-坡谷 whoop（1 / 5 / 2.5 / 6），再俯冲进入发夹 |
| 发夹 | **+1.5，全圈最低**，坐在真实凹地里 |
| 收尾 | 2 → 3.5 → 3 → 2 回到起跑直道 |

总落差 **33 m**（上游是 10 m）。地形不是“把路抬起来”，而是在 `natural()` 里**真造了地形**（`LANDFORMS`：山顶丘 + 肩脊 + 桥丘 + 发夹凹地），这样路是“切进山里”，而不是骑在一座土包上。地形融合半径 72 m。

新增：第 3 个跳台（坡顶跨顶处）、桥前爬坡的加速板（共 10 块）。

### 12.2 相机接地（必须的修复）

陡降时相机在车后 6.5 m，那个位置的**地面比车高**（-24% 坡）+ 路肩边坡 → 相机埋进土里（实测截图：满屏草地、车不见）。修法：

- `environment.js` 导出 `groundAt(x,z)`（＝ `heightAt`），`track.js` 透传；
- `camera.js` 新增 `_groundAt()` + `CAM_GROUND_CLEAR = 1.6`，`camY` 夹到不低于「相机自身位置下方地形 + 1.6 m」，`snap()` 里同样夹。

修完实测：车后相机离地 2.0 m（之前埋在地下）。

### 12.4 两个环境坑（给后来人）

1. **水位**：一开始把发夹做到了 -6，而水面在 -1 → 路面周围地形被拉到 -6.6，**整段发夹泡在水里**（有截图证据）。现在全圈最低 +0.1，地形不低于 -0.6，安全。
2. **融合半径**：试过 110 m，结果整座岛被拉成一个圆包、赛道像刻在一个大饱脸上；最终用 72 m + 真实地形地物。

## 13. 第三轮：打磨

### 13.1 修掉的真实缺陷

| # | 缺陷 | 根因 | 修法 |
|---|---|---|---|
| 1 | **所有手绘文字都是黑底黑字**（ILLINOIS 大牌、GO ILLINI 旗、入口标牌全是空板） | 把 `THEME` 的**数字**色值传给了 canvas `fillStyle`；非法赋值被静默忽略 → 默认黑底 + 黑字 | `landmarks.js` 加 `cssColor()` 归一化（数字 → `#rrggbb`），三处调用改传 `THEME_CSS` |
| 2 | 相机在陡降段埋进土坡（满屏草地、看不见车） | 相机高度只相对车算，没算**相机自己脚下**的地形；-24% 坡上机位后方地面比车高 | `environment.js` 导出 `groundAt()`；`camera.js` 加 `CAM_GROUND_CLEAR = 1.6` 夹（`update()` 与 `snap()`）|
| 3 | 跳台黄箭头看起来指向**侧向** | 跳台面实际 20 m 宽 × 9 m 长，贴图画的是方形箭头 → 被横向拉扁 | 按真实比例重画 `makeRampTexture()`（窄 u、满 v）|
| 4 | 道口铁轨/标牌被推到 50 m 外山坡上 | 局部坐标搞反：局部 **+Z 是朝向赛道**，路面中心在 `+(wall+past)`，我写成了负号 | 改为 `zc = wall + past`，标牌放到横向 16 m（路肩）|
| 5 | 铁轨与路面**共面**（都在 +0.02）→ 看不见 | z-fighting | 铁轨抬到路面以上 4–7 cm |
| 6 | 建筑背光面接近纯黑 | 半球补光偏弱 | hemi 1.25 → 1.45 |
| 7 | **草地盖住柏油**（t≈0.51 的桥引道与 t≈0.615 的出口两段） | 桥面区间会关掉“地形拉平到路面”（`bridge`），而我恰在那条 `lakeDist 120–153` 的带上放了一座 +16 m 的“桥丘”地物 → 自然地形比路面高 5 m，实测 209 个地形顶点高于路面 | 删掉那座地物（桥本来就该是跨水高架），并给 `heightAt` 加硬上限：路面足迹（`|lat| ≤ halfWidth+4`）内地形不得高于 `L.roadTop(i,lat) - 0.45`；实测 **209 → 0** 个，最高差从 +5.7 m 变为 -0.36 m |

### 13.2 新增

- **弯道倾斜（banking）**：按曲率给弯道加内倾，上限 8°（`MAX_BANK = 0.14`），桥面强制为 0。所有剖面共一个入口 `bankDy(i, lat)`：路面/路缘/路肩/护栏/轮胎墙/加速板/跳台/道具盒全部跟随；`getSurfaceInfo()` 的高度加上了 `tan(bank)·lat`，法线换成 `(right + up·tan bank) × tangent`。车模本来就会用地面法线滚转（`kart.js _animate`），所以手感是白送的。
- **坡顶 ILLINOIS 大牌**（landmark #13）：46 m 宽，坐在大左扫弯外侧坡面，爬坡全程可见、跨顶后回头仍在。
- **后段铁路道口**（landmark #14）：枕木 + 双轨（纯装饰、无碰撞）+ 两侧红闪灯与 X 牌。
